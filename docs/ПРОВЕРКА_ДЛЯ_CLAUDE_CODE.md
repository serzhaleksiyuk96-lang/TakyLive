Ты работаешь на Windows-ПК стримера через Claude Code. Твоя задача — проверить, что

просто, без жаргона: он не программист.

## Что такое TakyLive

Программа для TikTok-стримов. Сервер на Python (aiohttp) слушает `127.0.0.1:8765`,
окно — Edge в режиме `--app`. Ловит события эфира TikTok (подарки, лайки, чат,
фолловы) и запускает по ним команды в игре (Minecraft, GTA 5, Rust и др.), озвучку,
оверлеи для OBS (`/web/overlays/*.html`).

Установленная версия лежит в `%LOCALAPPDATA%\Programs\TakyLive` (`TakyLive.exe`).
Исходники: https://github.com/serzhaleksiyuk96-lang/TakyLive (ветка `main`).

## Жёсткие правила

1. **Данные стримера не трогать.** В установленной папке и в любой его папке TakyLive
   не изменяй и не удаляй: `config.json`, `profiles.json`, `viewer_voices.json`,
   `viewer_points.json`, `reports\`, `servers\`, `media\`, `fish_key.txt`. Нужно посмотреть —

2. **Проверяй на отдельной копии**, а не на установленной программе (см. шаг 1).

   `TAKY_PORT=<порт>` — свой порт, чтобы не мешать установленной программе.
3. **Ничего не публикуй.** Никаких `git push`, тегов, релизов на GitHub, постов

   у стримера; в отчёт их не пиши.
5. **Не запускай игры и игровые серверы**, не ставь моды без просьбы.
6. **Не меняй системные настройки** (брандмауэр, автозагрузку, реестр). Если Windows
   показывает окно брандмауэра — объясни стримеру, что нажать, и пусть нажмёт он.
7. Ошибку можно поправить только в тестовой копии, в локальной ветке `test-fixes`,
   без push. Каждую правку опиши в отчёте (файл, что было, что стало, почему).
8. Если что-то неясно или действие нельзя отменить — спроси стримера.

## Шаг 2. Автопроверка

Скрипт сам копирует программу во временную папку, запускает её в тестовом режиме
на свободном порту и гоняет все механики через API: подарки, очки, чат-команды
за очки, битву, колесо, итоги, пульт, защиту от чужих сайтов, ИИ-соведущего
на встроенном поддельном ИИ (интернет и деньги не нужны).

**Перед запуском** скажи стримеру: при проверке пульта Windows может спросить про
брандмауэр для `python.exe`. Можно нажать «Разрешить» (частные сети) или «Отмена» —
на автопроверку это не влияет. Если не хочет окна — запусти с `--no-remote`.

```powershell
python tools\smoke_test.py            # всё
python tools\smoke_test.py --no-remote
```

Первый запуск ставит библиотеки (aiohttp, TikTokLive 7.0.1, edge-tts, segno…) —
до 5 минут. В конце: `Итого: N PASS, M FAIL`, файл `smoke_test_result.txt`. При FAIL
временная копия остаётся — путь напечатан; там `app_output.txt` (вывод программы).

На каждый FAIL: найди причину в коде, проверь вручную (шаг 3), запиши в отчёт.
Сам скрипт тоже может ошибаться — если уверен, что неправ тест, а не программа, так и напиши.

## Шаг 2½. Связь с TikTok — приходят ли чат и лайки

Важно: в прошлом эфире программа видела зрителей и фолловы, но не видела ни одного
сообщения и лайка. Нужно понять, это TikTok не присылал или программа не читает.
У стримера стоит Python 3.14 — проверь и на нём, и (если есть) на 3.12.

Попроси у стримера ник любого идущего эфира с живым чатом (100+ зрителей) или найди
сам на tiktok.com/live и спроси, можно ли к нему подключиться (это только чтение):

```powershell
python tools\tiktok_probe.py <ник> 90
```

Скрипт напишет, сколько пришло чата, лайков, подарков, входов и сколько прочитано.
Запиши вывод в отчёт целиком. Если «приходят, но не читаются» — это главный баг,
приложи версии Python и TikTokLive (`python -m pip show TikTokLive betterproto2`).

Потом в тестовой копии: подключись к тому же эфиру из окна программы и через 2 минуты
посмотри журнал — строки `TIKTOK 📡 За минуту пришло: …` должны совпадать с пробой.

### Обновление: всё ли остаётся на месте (важно — на Windows!)

На Windows обновление ставит настоящий `apply_update.bat` (robocopy), и проверить его можно
только на Windows. Скрипт собирает «старую» копию с эдитами, музыкой, вкладками, очками,
серверами, поднимает поддельный GitHub с «новой» версией и жмёт «Обновить»:

```powershell
python tools\update_test.py
```

Должно быть `Обновление: N PASS, 0 FAIL`. Откроется окно `TakyLive: обновление` и потом окно
программы в тестовом режиме — в конце скрипт закроет её сам (окно «Press any key» можно закрыть).
При FAIL папка остаётся — приложи из неё `app_output.txt` и содержимое `_update\`.

Ещё проверь руками на тестовой копии:
- [ ] Открой программу, потом запусти её второй раз (ярлык / `python app.py`): вторая копия
  не стартует, а в старом окне появляется заглушка «TakyLive открыт в другом окне» с кнопкой
  «Работать в этом окне». Изменения из окна-заглушки не сохраняются.
- [ ] Настройки → «🛟 Резервные копии»: есть копия «запуск»; «➕ Сделать копию сейчас» →
  поменяй что-нибудь во вкладке → «↩ Вернуть» → всё как было.
- [ ] Загрузи эдит `.mov` и поставь в карточку: после «готовлю видео для OBS» карточка
  показывает `.mp4`, а не «⚠ файл не найден». Загрузи другой файл с тем же именем —
  старый не затирается, новый получает имя с «(2)».

### Русские названия подарков

Карточки с русскими названиями («Кулон дружбы») срабатывают, только если программа знает
перевод (TikTok присылает в эфир английские «Friendship Necklace»). Проверь, отдаёт ли
TikTok русский список:

```powershell
python tools\tiktok_probe.py <ник идущего эфира> --ru
```

Скрипт сохранит `gift_names_ru_full.json` — приложи его к отчёту (его встроят в программу,
чтобы русские карточки работали у всех сразу) и запиши, какой «способ» сработал.

## Шаг 3. Ручная и визуальная проверка (на тестовой копии)

Запусти копию в отдельном окне терминала и оставь работать:

Вкладку в профиле создай через окно (`http://127.0.0.1:8799` в Edge) или положи

```powershell
$u = "http://127.0.0.1:8799"
function Sim($o) { Invoke-RestMethod "$u/api/simulate" -Method Post -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes(($o | ConvertTo-Json))) }
Sim @{kind="gift"; name="Rose"; gift_id="5655"; count=3; user="Аня"; diamonds=1}
Sim @{kind="chat"; user="Kirill"; text="!к"}
Sim @{kind="like"; user="Аня"; count=200}

Invoke-RestMethod "$u/api/wheel/spin" -Method Post
Invoke-RestMethod "$u/api/log" | Select -Expand log | Select -Last 15
```

Важно: тело запроса — в UTF-8 (как выше), иначе русские ники превратятся в «????».

## Шаг 5. Отчёт

Создай папку `%USERPROFILE%\TakyLive_test\отчёт_<ГГГГ-ММ-ДД>\` и сложи туда: `ОТЧЁТ.md` (формат ниже),

`tiktok_probe.py`, папку `shots\` со скриншотами, при FAIL — `app_output.txt`. В конце упакуй её
в `отчёт_<дата>.zip`. Ничего не коммить. Ключи и токены в отчёт не пиши. Формат:

```markdown
# Проверка TakyLive <версия> — <дата>

## Итог
Автопроверка: N PASS / M FAIL. Главное одним абзацем: что работает, что сломано.

### 🔴 Критично (программа падает, теряются данные, не работает основное)

### 🟡 Мелочи (внешний вид, тексты, неудобства)
Для каждой: что делал → что ожидал → что получил, скриншот или кусок лога,

## Что не проверено и почему
```

## Если что-то пошло не так

- `Address already in use` / порт занят — выбери другой `TAKY_PORT`.
- Копия не стартует — смотри вывод в терминале или `app_output.txt` из временной папки.
- Русские буквы «кракозябрами» в терминале — `chcp 65001`, `$env:PYTHONUTF8="1"`.
- Закончил — останови копию (Ctrl+C), временные папки `takylive_smoke_*` в `%TEMP%`
  можно удалить. Установленную программу не трогай.
